# 实验三：UML 建模

## 1. 参与者（Actor）

| 参与者 | 说明 |
| --- | --- |
| 学生 | 注册登录、浏览/搜索设备、提交预约、取消预约、提交报修、查看记录/公告/消息、加入候补 |
| 实验室管理员 | 设备 CRUD、预约审核、处理报修、发布公告、候补管理、导出报表、标记完成/爽约 |
| 超级管理员 | 账号管理、角色分配、黑名单管理、系统参数配置、查看日志、数据备份恢复 |

## 2. 用例图

### 2.1 学生用例图

参与者：**学生**

用例：登录系统、修改个人信息、浏览设备列表、搜索设备、提交预约申请、取消预约、加入候补、查看我的预约记录、提交故障报修、查看报修进度、浏览系统公告、查看站内消息。

包含关系：
- 提交预约申请 **包含** 时间冲突校验、时长校验、黑名单校验。

### 2.2 管理员与超管用例图

**实验室管理员**：登录、设备信息管理、预约审核、处理报修工单、发布公告、导出预约报表、候补管理、标记完成/爽约。

**超级管理员**：账号管理、角色分配、黑名单管理、系统参数配置、查看系统操作日志、数据备份恢复。

## 3. 核心用例规约

### 3.1 提交预约申请

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-01 |
| 参与者 | 学生 |
| 前置条件 | 学生登录成功，账号不在黑名单，设备状态非维修/报废 |
| 后置条件 | 校验通过生成「待审核」预约记录；校验失败不生成记录 |
| 基本流程 | 学生选设备 → 选起止时间 → 系统多重校验（非过去时间、时长≤上限、无时段冲突、非黑名单）→ 保存预约记录 → 提示等待审核 |
| 异常流程 | 时间冲突 / 时长超限 / 黑名单 / 设备维修报废 → 返回失败提示 |

### 3.2 预约审核

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-02 |
| 参与者 | 实验室管理员 |
| 前置条件 | 存在待审核预约 |
| 后置条件 | 状态更新为通过/驳回；通过时推送消息、设备置「占用」 |
| 基本流程 | 查看待审核列表 → 选择通过/驳回 → 驳回填理由 → 更新状态 → 通知学生 |
| 异常流程 | 驳回未填理由 / 审核时发现新冲突 → 提示 |

### 3.3 取消预约触发候补转正

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-03 |
| 参与者 | 学生（本人）/ 管理员 |
| 前置条件 | 预约处于待审核/已通过 |
| 后置条件 | 预约置「已取消」；设备恢复空闲；最早候补者自动转正并收到消息 |
| 基本流程 | 选择预约 → 确认取消 → 更新状态 → 查询最早候补 → 生成新预约 → 通知候补者 |

## 4. 用例关系说明

- **包含（include）**：提交预约申请包含「时间冲突校验」「时长校验」「黑名单校验」，被包含用例是提交预约的必要子步骤。
- **泛化（generalization）**：学生、实验室管理员、超级管理员均为「用户」的特化角色。
- 本系统无 extend（扩展）关系（可选功能均已纳入主流程）。
