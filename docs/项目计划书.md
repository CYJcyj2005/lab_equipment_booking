# 实验室设备预约系统项目计划书

> 落地说明：本文档为项目的总体愿景与建设计划。其中「技术选型建议」为企业级 Web 架构的**目标愿景**；本课程设计实际落地采用 **PyQt6 + SQLite + MVC 桌面版 + Flask/H5 移动端**，功能需求已按桌面版技术栈逐项适配实现。

---

## 一、项目概述

### 1.1 项目背景
高校/科研机构实验室设备存在使用冲突、闲置率高、管理混乱等问题，需要一套信息化系统实现设备的高效预约、审批、使用追踪与统计分析。

### 1.2 项目目标
- 实现设备全生命周期管理（入库→预约→使用→维护→报废）
- 支持多角色协同（管理员、教师、学生、审批人）
- 提供可视化预约日历与冲突检测
- 数据驱动决策（使用率统计、报表导出）

### 1.3 目标用户
| 角色 | 核心需求 |
|------|---------|
| 系统管理员 | 用户管理、设备管理、权限配置、数据统计 |
| 设备管理员 | 审批预约、设备维护、故障上报 |
| 教师/导师 | 预约设备、查看课题组使用情况 |
| 学生 | 预约设备、签到签退、查看个人记录 |
| 财务/审计 | 费用结算（如收费设备）、报表查看 |

## 二、功能模块设计

### 2.1 用户与权限模块
- 注册/登录（学号/工号认证、邮箱验证、SSO对接）
- 角色权限管理（RBAC模型）
- 个人信息管理、信用分体系（违约扣分）
- 黑名单/白名单机制

### 2.2 设备管理模块
- 设备台账（名称、型号、编号、位置、图片、说明书）
- 分类管理（按实验室、类型、贵重等级）
- 状态管理（可用/占用/维护/报废/预约中）
- 二维码/RFID标签生成与扫码查看
- 附件管理（操作手册、安全须知）
- 设备参数与预约规则配置（最短/最长时长、提前预约天数、是否需审批）

### 2.3 预约管理模块（核心）
- **日历视图**：日/周/月视图，拖拽选择时段
- **冲突检测**：实时校验时间重叠、设备状态
- **预约类型**：
  - 即时预约（先到先得）
  - 审批预约（需管理员审核）
  - 周期性预约（如每周一 9:00-11:00）
  - 排队候补（满员时加入等待队列）
- **预约规则**：
  - 信用分门槛
  - 单用户同时预约上限
  - 提前取消时限
- **审批流**：多级审批（导师→设备管理员）、批量审批、审批意见
- **提醒通知**：短信/邮件/站内信/微信推送（预约成功、即将开始、超时未签到）

### 2.4 使用与签到模块
- 扫码签到/签退
- 超时自动释放与违约记录
- 使用日志（开始时间、结束时间、实际使用人）
- 设备状态实时更新
- 故障上报入口

### 2.5 维护与故障模块
- 故障报修工单
- 维护计划（定期保养提醒）
- 维修记录与成本统计
- 设备停机时间统计

### 2.6 统计与报表模块
- 设备使用率排行
- 预约趋势图（按日/周/月）
- 用户违约统计
- 实验室利用率热力图
- 导出 Excel/PDF 报表
- 费用结算（可选：按小时计费）

### 2.7 通知与消息模块
- 站内消息中心
- 模板管理（可自定义通知内容）
- 多渠道推送配置

### 2.8 系统管理模块
- 操作日志审计
- 数据备份与恢复
- 参数配置（预约规则、信用分规则）
- 接口管理（对接校园统一认证、门禁系统）

## 三、技术架构

### 3.1 技术选型建议（目标愿景）

| 层次 | 技术方案 |
|------|---------|
| 前端 | Vue3 + Element Plus / React + Ant Design |
| 移动端 | 微信小程序 / H5 响应式 |
| 后端 | Spring Boot / Django / Node.js (NestJS) |
| 数据库 | MySQL + Redis（缓存/队列） |
| 消息队列 | RabbitMQ / Kafka（通知、候补） |
| 文件存储 | MinIO / 阿里云 OSS |
| 定时任务 | XXL-Job / Quartz |
| 部署 | Docker + Nginx，可选 K8s |
| 认证 | JWT + OAuth2 / CAS 对接 |

### 3.2 系统架构图（文字描述）
```
客户端(Web/小程序) → API网关 → 微服务/单体应用
                              ├─ 用户服务
                              ├─ 设备服务
                              ├─ 预约服务（核心）
                              ├─ 通知服务
                              └─ 统计服务
                                    ↓
                        MySQL / Redis / MQ / OSS
```

### 3.3 关键数据表设计（简）
- `user`（用户）
- `role` / `permission` / `user_role`
- `device`（设备）
- `device_category`
- `reservation`（预约单）
- `reservation_rule`
- `approval_flow` / `approval_record`
- `usage_log`（使用记录）
- `fault_report`（故障）
- `maintenance_record`
- `notification`
- `credit_log`（信用分变动）

## 五、非功能性需求

- **性能**：支持 500+ 并发，预约响应 < 1s
- **安全**：防SQL注入、XSS、CSRF，敏感数据加密，操作审计
- **可用性**：99.5% 可用，支持水平扩展
- **兼容性**：Chrome/Edge/Firefox，移动端适配
- **可维护性**：模块化、日志完善、API文档（Swagger）

---

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 需求变更频繁 | 敏捷迭代，每2周评审 |
| 预约并发冲突 | Redis分布式锁 + 数据库唯一约束 |
| 用户不配合使用 | 培训 + 扫码便捷入口 + 激励机制 |
| 设备数据不准 | 定期盘点 + 扫码核对 |
| 系统集成困难 | 提前对接统一认证/门禁接口 |
