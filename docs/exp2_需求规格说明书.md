## 2. 系统概述

### 2.1 产品描述

本系统为独立桌面应用（PyQt6 GUI），解决实验室设备预约冲突、故障上报不及时、台账管理混乱等问题。

**目标**：
- **决策支持**：提供预约统计与设备使用率报表，辅助资源调配；
- **提高效率**：替代纸质登记，自动冲突检测，减少人工失误。

#### （2）用例模型

参与者与用例见《实验三 UML 建模》。

#### （3）业务流模型

- **启动阶段**：学生注册 → 管理员录入设备 → 发布初始公告；
- **预约阶段**：学生浏览设备 → 选择时段 → 系统校验 → 提交申请 → 管理员审核 → 通过/驳回；
- **使用阶段**：学生按时使用 → 管理员标记完成/爽约 → 爽约累计判黑名单；
- **异常阶段**：设备故障 → 学生报修 → 管理员处理 → 状态流转；
- **统计阶段**：管理员导出报表 → 超管查看日志/配置参数/备份恢复。

### 2.3 一般约束

- **假定**：用户具备基本计算机操作能力；提供 Windows 测试环境。
- **约束**：交付日期按课程进度；单机桌面应用，不支持多机并发写入。
- **限制**：基于 Python + PyQt6 + SQLite，不使用 Web 框架。

## 3. 功能性需求分类

> 每个功能按「功能说明 + 参与者 + 用例规约」描述。

### 3.1 用户账号模块

**3.1.1 学生注册**

- 功能说明：学生填写用户名、密码、真实姓名、手机号注册，密码 bcrypt 加密存储。
- 参与者：学生。
- 用例规约：
  - 前置：未登录，用户名未被占用；
  - 后置：生成 status=正常 的学生账号；
  - 基本流：填写信息 → 校验唯一性与格式 → 加密密码 → 写入 user 表 → 提示成功；
  - 异常流：用户名重复 / 密码不足 6 位 / 手机号格式错误 → 返回失败提示。

**3.1.2 登录**

- 功能说明：全角色登录，校验密码、账号状态（黑名单禁用）。
- 参与者：学生、实验室管理员、超级管理员。
- 用例规约：
  - 前置：账号存在且 status=正常；
  - 后置：进入对应角色主窗口；
  - 基本流：输入账号密码 → 校验 → 跳转；
  - 异常流：密码错 / 账号禁用 → 弹窗提示。

**3.1.3 账号管理（超管）**

- 功能说明：新增账号、角色分配、重置密码、禁用/启用。

### 3.2 设备管理模块

**3.2.1 设备 CRUD（管理员）**

- 功能说明：新增、编辑、报废设备；维护分类、实验室、规格、状态。
- 参与者：实验室管理员。
- 用例规约：
  - 前置：管理员已登录；
  - 后置：device 表更新；
  - 异常流：设备编号重复 / 必填项为空 → 提示。

**3.2.2 设备浏览与搜索（学生）**

- 功能说明：按名称、编号、分类搜索；维修/报废设备禁止预约。
- 参与者：学生。

### 3.3 预约核心业务模块（重点）

**3.3.1 提交预约**

- 功能说明：学生选设备、选起止时间提交申请，系统多重校验。
- 参与者：学生。
- 用例图：学生 → 提交预约 → 包含「时间冲突校验」「时长校验」「黑名单校验」。
- 用例规约：
  - 前置：学生登录，不在黑名单，设备状态非维修/报废；
  - 后置：校验通过生成 audit_status=待审核 记录；失败不生成；
  - 基本流：选设备 → 选时间 → 校验①非过去时间 ②时长≤上限 ③无冲突 ④非黑名单 → 写入 appointment → 提示等待审核；
  - 异常流：任一校验失败 → 返回具体原因。

**3.3.2 预约审核（管理员）**

- 功能说明：查看待审核列表，通过/驳回并填理由。
- 参与者：实验室管理员。
- 用例规约：
  - 前置：存在待审核预约；
  - 后置：audit_status 更新为通过/驳回；通过时触发消息通知并置设备为「占用」；
  - 异常流：驳回未填理由 / 审核时发现新冲突 → 提示。

**3.3.3 取消预约（学生/管理员）**

- 功能说明：待审核/已通过的预约可取消；本人或管理员可操作；取消后触发候补转正。
- 用例规约：
  - 前置：预约处于待审核/已通过；距开始时间≥30 分钟（已通过时）；
  - 后置：状态置为已取消，设备恢复空闲，最早候补者自动转正并收到消息。

**3.3.4 爽约判定与黑名单**

- 功能说明：管理员对「已通过」预约标记完成/爽约；爽约累计达阈值自动禁用账号（黑名单）。
- 参与者：实验室管理员（标记）、超级管理员（管理黑名单）、系统（自动判黑名单）。

### 3.4 故障报修模块

- **提交报修（学生）**：选设备、填故障描述提交报修单。
- **处理报修（管理员）**：状态流转 待处理→维修中→已修复，更新设备状态并通知报修人。

### 3.5 公告通知模块

- **发布公告（管理员）**：填写标题、内容发布，并向全员推送站内消息。
- **查看公告（全角色）**：查看公告列表。

### 3.6 统计与系统模块

- **导出预约报表（管理员）**：按时间范围导出 CSV，支持设备使用率统计。
- **系统日志（超管）**：查看全部操作日志。
- **系统参数配置（超管）**：配置预约最大时长、黑名单阈值（实时生效）。
- **数据备份与恢复（超管）**：备份 SQLite 到 backup 目录，支持恢复。

### 3.7 候补队列模块

- **加入候补**：目标时段已被占满时，学生可加入候补队列。
- **候补转正**：预约取消时，系统按候补顺序自动为最早候补者生成「待审核」预约并通知。
- **候补取消**：学生可主动取消候补。

### 3.8 站内消息模块

- **消息推送**：审核结果、报修进度、公告发布、候补转正时自动生成站内消息。
- **消息中心**：查看消息列表，标记已读/全部已读。

## 4. 非功能性需求

### 4.1 外部接口说明

**4.1.1 用户接口**

- 独立桌面 GUI 窗口，居中显示，操作提示友好；
- 非法输入弹窗提示，危险操作二次确认；
- 主窗口采用左侧导航 + QStackedWidget 堆叠页面。

**4.1.2 软件接口**

| 接口 | 说明 |
| --- | --- |
| SQLite | Python 内置 sqlite3 访问，DAO 层统一封装 |
| pandas | CSV 报表导出 |
| bcrypt | 密码加密 |
| PyInstaller | 打包 exe，无需 Python 环境 |

### 4.2 性能需求

**静态数值需求**：
- 单机单用户桌面应用；
- 界面切换响应时间 < 1s；
- 登录校验响应 < 500ms。

**动态数值需求**：
- 支持数百条预约记录稳定运行；
- 单表 10 万条记录查询 < 2s；
- 报表导出 1000 条记录 < 3s；
- 数据库文件异常关闭不丢失（事务提交）。

**4.2.1 硬件的限制**

- 最低配置：Windows 10 / 4GB 内存 / 500MB 磁盘 / 1366×768；
- 推荐配置：Windows 10/11 / 8GB 内存 / 1GB 磁盘 / 1920×1080。

### 4.3 属性

**4.3.1 友好性**：界面简洁，导航清晰，错误提示具体可操作；表格支持排序、筛选。

**4.3.2 安全性**：密码 bcrypt 加密；严格角色权限隔离；关键操作记录 sys_log；黑名单拦截。

**4.3.3 可维护性**：MVC 分层，界面与业务解耦；每个类、核心函数有文档字符串。

**4.3.4 可转移/换性**：SQLite 文件可迁移；支持 Windows 打包 exe 跨机器运行。

### 4.4 系统的运行环境

- 起始运行：双击 exe 或 `python main.py`；
- 结束运行：关闭主窗口或退出登录；
- 数据库初始化：首次运行自动建表并初始化超管。

### 4.5 其他需求

- 初始化操作：首次运行创建数据库、初始化超管（admin/admin123）、种子数据；
- 数据处理：预约提交、审核、报修、导出；
- 后援恢复：超管可备份/恢复数据库。

## 5. E-R 图和数据字典

### 5.1 E-R 图

**实体**：User、Lab、Device、Appointment、Repair、Notice、SysLog、Waitlist、Message、Setting。

**关系**：
1. User(1) — (N) Appointment；
2. Device(1) — (N) Appointment；
3. User(1) — (N) Repair；Device(1) — (N) Repair；
4. Lab(1) — (N) Device；
5. User(1) — (N) Waitlist；Device(1) — (N) Waitlist；
6. User(1) — (N) Message（接收者）；
7. User(1) — (N) SysLog；
8. User(1) — (N) Notice（发布者）。

**主键**：各表自增 ID（setting 表以 skey 为主键）。
**外键**：appointment(uid, did)、repair(uid, did)、waitlist(uid, did) 分别参照 user.uid、device.did。
