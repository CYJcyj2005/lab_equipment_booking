# 实验室设备预约系统 —— 核心模块代码

本目录为软件工程课程设计《实验室设备预约系统》的**核心模块代码实现**（实验 6、实验 9），
采用 Python 3 编写，遵循 PEP 8 编码规范。

## 项目结构

```
code/
├── main.py                        # 演示入口（完整预约闭环）
├── cli.py                         # 交互式命令行入口（登录测试用）
├── lab_reservation/               # 核心业务包
│   ├── __init__.py                # 包导出
│   ├── models.py                  # 数据模型（用户/设备/实验室/预约单/使用记录）
│   ├── exceptions.py              # 自定义业务异常
│   ├── repositories.py            # 内存数据仓库（仓库模式，可替换为数据库）
│   └── services.py                # 业务逻辑层（预约/审核/设备/用户服务）
└── tests/                         # 单元测试（实验 9）
    ├── common.py                  # 测试夹具
    ├── test_reservation.py        # 预约/审核/使用登记测试
    ├── test_equipment.py          # 设备管理测试
    └── test_user.py               # 用户注册/登录测试
```

## 模块划分与职责

| 模块 | 职责 | 对应 SRS 章节 |
| --- | --- | --- |
| `models.py` | 实体与枚举定义，对应数据字典各表 | 6.1 |
| `repositories.py` | 数据存取（仓库模式，解耦业务与存储） | 5.2 |
| `services.py` | 业务规则：冲突检测、状态机、权限校验 | 3.3 / 3.4 / 3.5 |
| `exceptions.py` | 业务异常分类 | 3.3 / 3.4 |

## 环境要求

- Python >= 3.10（使用 `date | None` 类型语法）
- 无第三方运行时依赖（测试使用标准库 `unittest`）

## 运行演示

```bash
cd code
python main.py
```

输出一次完整预约闭环：注册 → 录入设备 → 提交预约 → 审核通过 → 签到 → 签退，
并演示时段冲突检测与不可用设备拦截。

## 核心业务规则说明

1. **时段冲突检测**：同一设备、同一日期、重叠时段且状态为“待审核/已通过”的预约视为冲突；
   时段比较采用开区间，首尾相接（如 08:00-10:00 与 10:00-12:00）不算冲突。
2. **用户单时段唯一**：同一用户同一时段只能持有一张有效预约单。
3. **状态机**：预约单 `待审核 → 已通过/已驳回`，`待审核/已通过 → 已取消`，`已通过 → 已完成`。
4. **权限校验**：普通用户只能操作本人预约，管理员可代操作。
5. **密码安全**：密码以 SHA-256 哈希存储（演示用，实际工程建议 bcrypt+盐）。

## 编码规范说明

- 命名：类用 `UpperCamelCase`，函数/变量用 `snake_case`，常量全大写；
- 每个模块、类、关键方法均带中文 docstring；
- 类型注解使用 `typing` 与 `from __future__ import annotations`。
